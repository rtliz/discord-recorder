# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```
npm install
npm start              # node src/index.js — registers global slash commands, then logs in
npm run drive-auth     # one-time OAuth flow on localhost:53682, prints GOOGLE_REFRESH_TOKEN for .env
npm run agent -- --server https://host --code 123456   # dev run of the recorder agent (first pairing); then `npm run agent`
npm run build:agent    # maintainer: re-download pinned Node/ffmpeg, rewrite src/agent/pins.json SHA-256s, print the diff (--dry, --bump node=<v>|ffmpeg=<v>)
ffmpeg -f avfoundation -list_devices true -i ""   # find SCREEN_DEVICE index (macOS)
```

There is no build step or linter. `npm test` (node:test, offline, no Discord login) and `npm run test:browser` (headless Chrome via puppeteer-core, skips without Chrome). `test/index-*.test.js` load `src/index.js` without logging in: the main-guard skips login and REST, and `deps` swaps recorders and uploads for fakes in `test/helpers`. Plain Node ESM (`"type": "module"`, top-level `await`). `ffmpeg` must be on PATH.
Verify changes by running the bot against a real Discord server. Copy `.env.example` to `.env` first.

## Architecture

A single-process Discord gateway bot. `src/index.js` holds all routing and state. Other modules are leaf helpers.
Flow diagrams (Mermaid) for every path are in `diagram/`. Update them when a flow changes.

- **State is in-memory, one screen recording per guild**: `voice: Map<guildId, VoiceRecorder>` and `screen: Map<guildId, ScreenRecorder | BrowserCapture | Session>` (a `Session` has `kind: 'session'`, see below).
  A recorder object also carries the context it needs later: `textChannel` (where to post the result), `by`/`owner`, and for auto recordings `auto` (sharer user id) and `autoChannelId`.
  A restart loses in-progress recordings. Nothing handles SIGTERM.
- **One handler for slash commands, buttons and selects**: a button `customId` is `"<cmd>:<sub>"` (for example `record:stop`). The `interactionCreate` handler parses slash commands, buttons and select menus into the same `[cmd, sub]` pair, so a new action needs an entry in `BUTTONS` (or `SELECTS`) and a branch in the handler. Bot replies carry the buttons for the next step (`row(...)`). `panel()` builds the control panel from the current state.
- **Permissions**: slash commands are gated by Discord (`ManageGuild` default permission). Buttons are visible to everyone, so the handler re-checks `ManageGuild`. If `ALLOWED_USER_IDS` is set, it replaces both checks. `/agent` is open to everyone (own devices); `isAdmin` there adds the server's devices and `agent:kick`, re-checked inside `handleAgent` on every press.
- **Voice** (`voice-recorder.js`): joins with `selfDeaf:false` and writes one raw PCM file per speaker (`<userId>.pcm`, 48kHz s16le stereo). Before each speaking burst it pads silence computed from `startedAt`, so all tracks stay time-aligned. On stop, ffmpeg `amix` merges the tracks into `voice.mp3`.
- **Screen** (`screen-recorder.js`, macOS only): ffmpeg `avfoundation` plus `h264_videotoolbox`. Missing Screen Recording permission makes ffmpeg hang silently, so `start()` waits up to 8 s for the first `frame=` on stderr and throws `code: 'SCREEN_PERMISSION'` on timeout. Stop sends `q` to stdin so the mp4 is finalized, escalating to SIGINT and then SIGKILL. Window mode gets a crop region (fractions of the main display) from `window-bounds.js` (osascript JXA) and throws `code: 'WINDOW_NOT_FOUND'`. The `errorButtons(e)` function maps error `code`s to recovery buttons.
- **Screen modes**: `macScreen = SCREEN_ENABLED !== 'false'` (host-Mac capture), `browserScreen = Boolean(PUBLIC_URL)`, `screenEnabled` is either. With `PUBLIC_URL`, `modes` is `['agent', 'browser']`: `agent` commands the person's recorder agent and falls back to the 🎥 link when they have none (or it fails); `browser` always uses the link and never commands an agent (`useAgent(g)`). The host-Mac modes `screen`/`window` are offered only without `PUBLIC_URL` (the ScreenRecorder code stays; `settings.js` reads a saved or env `screen`/`window` as `agent` when `PUBLIC_URL` is set). `modeOf(settings)` falls back to `modes[0]`, `isMac(mode)`. The mode applies to every share start (🔴, auto, 🔁, 🔴 ต่อ, auto continue, the agent upgrade); a manual 🖥️ session (`screen:me`, `sess.mode === 'manual'`) commands the presser's agent whatever the mode; the panel's own buttons ignore it (see Private offers). `screenBusy()` ignores browser captures: Mac screen is one at a time globally, browser capture is one per guild.
- **Browser capture** (`browser-capture.js`, `capture-server.js`, `capture/page.*`): Discord bots cannot receive video, so the sharer records their own screen. A `BrowserCapture` (same shape as `ScreenRecorder`: `stop()` returns the path, `exited`, `stopping`) lives in the `screen` Map. States: `offered` -> `live` -> `stopping` -> `finalizing` -> `done`, plus `voice` (phone fallback, see below). A capture from a pressed share card has no timer (`offerMs: 0`: it ends on stop, share end, leave or max); only manual private offers expire, after 5 min. The sharer opens the link on the session card; a manual sharer presses `screen:me` for an ephemeral link instead. `via: 'agent'` marks a capture driven by a recorder agent (same chunk API, `what: 'จอ (ตัวอัด)'`, agent exit texts); `exitKind` is `local` (owner stopped, offer lapsed), `gone` (heartbeat, unload) or `cap` (size caps). Links are HMAC-signed with a per-process random key and claimed once: the manual link lasts 10 min, the session card's link is minted once (`rec.cardLink`, lasts `maxMinutes` or 24 h). The page runs `getDisplayMedia` + `MediaRecorder` and PUTs numbered 3 s chunks with a bearer session. `stop()` waits for the page to flush, then pipes the chunks into ffmpeg (remux only, never re-encode; H.264 -> mp4, VP8/VP9 -> webm, falls back to the raw concatenation). Every self-exit (manual offer 5 min timeout, heartbeat 45 s, size cap `CAPTURE_MAX_MB` or the process-wide `CAPTURE_TOTAL_MB`, page stop/ended/unload) sets `exitReason` and `exitSkip`, so the finish path reports it and `cardSkip` blocks re-offering until the sharer stops sharing. The owner may press `screen:me`/`screen:stop` without the recorder role. The modules must not import discord.js or index.js, and only use node built-ins.
- **HTTP server** (`startCaptureServer`, plain `node:http`, `maxConnections` = `HTTP_MAX_CONNECTIONS` or 512 because every online agent holds a long-poll): starts when `PUBLIC_URL` is set (full routes) or only `HTTP_PORT` is set (health only: `/healthz` 200, else 404). Page and agent assets are read once into memory, never served from disk by URL. Capture routes: `/capture/<token>`, `/static/capture.{js,css}`, `/api/capture/<capId>/{start,chunk/<seq>,status,stop}`. Agent routes: `/agent/{install.sh,install.ps1,manifest.json,files/<name>}` (public, generic, no secrets; `__SERVER__` replaced by `PUBLIC_URL`) and `/api/agent/{pair,hello,poll,ack,state}` (`agent-hub.js` `handle()`).
- **Press-to-start** (`checkShares`, `roomCards`, `cardSkip`): in `card` mode nothing records, joins voice or commands an agent without a press (auto voice is gone; `auto` mode below is the only exception). `checkShares` runs on every non-bot `voiceStateUpdate`, after a settings change, on a 1-minute sweep and when an agent comes online. For each watched room with `shareCards` on (`shareMode` `card` or `auto`), in schedule, with `minMembers` met, it keeps one card listing the sharers (filtered by `canShare`, `minShareSeconds`, `cardSkip`, not already in the session): `🖥️ <@B> กำลังแชร์จอใน **Room** · กด 🔴 เพื่ออัด`, one green `screen:rec:<userId>` button per sharer (max 3). No sharers left deletes the card. `roomCards: Map<voiceChannelId, rc>` (`rc.cardQ`, `rc.remember`); ids are kept in `settings.roomCards` and deleted on `clientReady` (`dropOrphanRoomCards`), then `checkShares` reposts. The session's own room has no room card.
  - `cardSkip: Map<guildId, Set<userId>>`: set on a local stop (D7), a failed/declined start (including a failed 🔁 / 🔴 ต่อ) and every finish (all the room's current sharers), all through `skipSharer`; cleared when the user stops streaming. Settings (cards off, schedule, rooms) gate only cards and auto starts: a running session is never ended by them. `skipSharer(guild, u)` adds only while `u` still streams (a skip added after the stop event would outlive the share).
- **Auto mode** (`shareMode: 'auto'`, `autoStart`, `autoNext`; the old flow: a share records at once and the bot joins): same filters as cards (`autoOn` = `screenEnabled` + auto + schedule; rooms, `minMembers`, roles via `canShare`, `minShareSeconds`, `cardSkip`).
  - Start: in `checkShares`, the first filtered sharer of a room (one with an agent online first, in mode `agent`) starts a session by itself when `busyText` is null (nothing records or starts in the guild), the room is `joinable` and (host Mac only) the Mac is free: `autoStart` = `newSession(..., by = sharer)` with `sess.auto`, the room card (if any) becomes the session card, then `launch(..., {auto:true})` (below). Without an agent the card shows `🔴 **กำลังอัดเสียงในห้อง …** · <@X> กด 🎥 เพื่ออัดจอด้วย` with the link (minted once, valid `maxMinutes` or 24 h, no expiry timer) and 📥; on the host Mac it records the Mac. If the sharer's agent comes online while their link is still unopened, `sessionEvent` switches the video to the agent once (`seg.upgrade`). A failed agent start skips them for auto (`skipSharer`) and falls back like no agent (the session keeps its audio). A failed join with no video cancels and skips them. A second room while one records gets its card; it may auto-start once the first session ends.
  - Continue: never an auto switch while a screen is live (🔁 stays a press). When the segment ends (`segmentEnded`) and the session waits, `autoNext` starts the first other sharer (one with an agent online first, else their link / the Mac) at once via `startScreen`, same session and file (mode `share` sessions only, also press-started ones); a start that gets no screen skips them and tries the next, then the normal 2-min wait. `sessionEvent` re-runs `autoNext` while waiting (a new sharer, an agent online, `minShareSeconds` reached). A machine that dropped or hit a cap (`exitKind` `gone`/`cap`) is in `sess.noAuto`: only a 🔴 ต่อ restarts it.
  - `onAgentChange(uid, true)` runs `checkShares` (via `setImmediate`, outside the hub's call) for the guilds they are in, so an agent coming online while its owner shares starts then.
  - Hand stop: `⏹️` finishes and skips every sharer of the room; `s` at the agent is D7 (skipped, continue on another sharer if any). Segments started by auto mode carry `seg.auto`: the live card adds `-# ⚡ อัดอัตโนมัติ ...`, the nickname status is `อัดจออัตโนมัติ`, and log lines end with `(อัตโนมัติ)`.
- **Session** (`kind: 'session'`, in the `screen` Map): one per guild (a bot has one voice connection per guild, so two rooms can't record together; a press in another room gets a busy reply). Created by `newSession(guild, room, textChannel, by, mode)`, which reserves `screen` synchronously. Fields: `state` `starting|live|waiting`, `mode` `share|manual`, `cur` (live segment), `pending`, `segments[{owner, source 'agent'|'link'|'mac', rec, done, error}]`, `paired` (the room audio: a legacy `VoiceRecorder` in the `voice` Map with `pairedTo = sess`, so panel, `voiceGone`, `record:stop` route unchanged), `card/cardQ`, `waitTimer/waitUntil`, `maxTimer`, `notes`, `finished`. Always re-check `screen.get(g) === sess` after any await.
  - **Start (old flow, `launch`)**: every new session (🔴 `pressRec`, `autoStart`, manual 🖥️ `agentManual`) calls `launch(sess, guild, uid, by)`: `joinSession` starts joining the room at once, in parallel with `startScreen`, and the card shows `🔴 **กำลังอัดในห้อง …**` with `⏳ กำลังสั่งเครื่องของ <@X> ให้เริ่มอัดจอ...` until the video is live (`sess.joinState` `joining|ok|fail` drives the `-# ⏳ บอทกำลังเข้าห้อง...` line and the red stop). `joinFailed` decides once both the join result and the first screen start are known, in either order: a failed join keeps the session only if a video is already live, with a note (R9); with no live video (an unopened link counts as none) the session is cancelled (`cancelSession`, which also skips `sess.want`). `pressRec` starts `launch` before `deferUpdate`, so a failed defer (10062) still lets the recording go ahead. `startScreen(sess, uid, by)`: the agent when (`sess.mode === 'manual'` or `useAgent`) and online (`startSegment(..., {agent:true})`); a failed agent start adds the Thai note (`agentFail`) and falls back with `startSegment(..., {agent:false})`: the card link (a manual session's link is `seg.private`, sent in the presser's reply), or the host Mac without `PUBLIC_URL` (a 🔁 on the Mac only relabels `cur.owner`). A share session falls back only while uid still shares; a share session left with audio only goes on, and `sessionEvent` treats `sess.want` stopping as the end of that screen (`nextScreen`). Returns `{seg, fail}`.
  - `screen:rec:<uid>` starts; `screen:switch:<began>.<uid>` (🔁) starts Y first and stops X only on success (one session, voice unbroken); `screen:cont:<began>.<uid>` (🔴 ต่อ) continues from the wait. Sharer named on the button may press it (`own`).
  - `segmentEnded` (sharer stops/leaves, agent drops, local stop): candidates = the room's sharers not in `cardSkip`. None, or a manual session -> `finishSession`. Otherwise state `waiting` for `T.wait` (2 min, exported for tests) with `🔴 ... ต่อ` buttons + `⏹️ จบ`; everyone leaving, `⏹️`, max length or expiry finish it. `voiceGone` on a live session adds a note and keeps the video; while waiting it finishes.
  - `finishSession` stops the segments and voice, awaits every `done`, then `deps.composeMeeting` (below) and delivers `meeting.*` as "▶️ ดูวิดีโอ" (fallback: up to 3 segment videos + voice.mp3 with a note). It sets `rec.result` on every browser segment (capture page redirect) and calls `dropUploaded` with all segment recs.
  - `screenBusy()` counts host-Mac segments inside sessions. Legacy manual 🎙️, manual 🖥️ (Mac), the manual browser private link without an agent and the phone voice fallback are unchanged and don't create sessions.
- **Recorder agent** (`src/agent/*` program, `src/agent-hub.js` server side, `src/agent/protocol.js` shared constants): a token-less program on the sharer's own machine records their screen when the bot says so. `/agent` and the `agent:install` button (📥 ติดตั้งตัวอัด, on the panel, the share card and the private link reply; ephemeral, registered only with `PUBLIC_URL`, exempt from `canRecord`) show one section per OS (`osSection`: `### 🍎 macOS / Linux`, then `### 🪟 Windows`), each with its own boxes for install/update (the one-liner with a one-time 128-bit token, 10 min), start later (`~/.discord-recorder-agent/start.command`, `& "$HOME\.discord-recorder-agent\start.cmd"`) and uninstall (`uninstall.command` / `uninstall.cmd`), one box per command so a copy never runs start and uninstall together; then `-# คำสั่งติดตั้งใช้ได้ครั้งเดียวถึง <t:…:t> (10 นาที)` (a clock time, never relative), `**🔗 เชื่อมใหม่**` with the 6-digit code boxed (start.command on an unpaired/revoked install prompts for it; without a code, a line to re-run the install command), and the user's devices (`agent:revoke:<deviceId>` / `agent:revoke:all` buttons).
  - Admin revoke: for `isAdmin` (ManageGuild, or `ALLOWED_USER_IDS`) the same reply adds `**ตัวอัดใน server นี้**` after เครื่องของคุณ: other users' devices in scope, `🟢/⚪ · <@owner> · name (os) · เห็นล่าสุด …`, newest first, one `agent:kick:<deviceId>` per device in the free rows (≤5 rows of 5, content ≤2000, `-# แสดง N จาก M`). Scope = devices paired from this guild (`guildId`, stored by `pair()` from the pairing since this change); an older record without `guildId` counts only while its owner is a member of this guild (`members.cache`, else one `members.fetch`, 1.5 s cap; at most 25 uncached owners per listing). Every `agent:kick` press re-checks `isAdmin` and scope (`🔒 ลบตัวอัดของคนอื่นได้เฉพาะผู้ดูแล server` / `ไม่พบเครื่องนี้ใน server นี้`), then `hub.revokeDevice(id)` (same as owner revoke: the live session gets `revoked`) and `rlog` `🗑️ <admin> ลบตัวอัดของ <owner> (<device>)`. A capture in progress: the agent hears `revoked`, deletes its credential and quits, which stops ffmpeg and posts stop `unload` with the capture token (still valid), so chunks already sent are kept and the segment ends as `gone` (`⚠️ ตัวอัดถูกปิด`, session waits / finishes as usual, `noAuto`). Hub listing: `allDevices()` (with `userId`, `guildId|null`, no secrets). The consent, macOS permission and capture-area notes are printed by the installer, not here. The 6-digit code is minted unless `AGENT_CODE_PAIRING=false` (k8s sets `"false"`, so there `/agent` shows the re-install line instead). The macOS/Linux one-liner is `curl -fsSL <PUBLIC_URL>/agent/install.sh | DRA_TOKEN=<token> sh` (env, not argv; `$1` still works for old commands); the commands are shown only when `PUBLIC_URL` is https (or localhost) and passes `SAFE_SERVER`. A hello with a new session on the same device ends a live capture only if it has been quiet for more than 2 chunks. Credential is `deviceId.secret`; `data/agents.json` (`AGENTS_FILE`) keeps only `sha256(secret)`, compared with `timingSafeEqual`, devices unseen for 90 days are pruned. Newest session of a user wins (the old one gets `replaced` and doesn't reconnect on its own).
  - Transport is HTTP long-poll (not WebSocket: no built-in server, passes the plain ingress). `poll` is held ~25 s; the agent is online while it polled within 40 s. Commands: `start {capId, token, maxMs, chunkMs, videoBps, room, by, area}` and `stop`; there is no ask (`askFirst` in an old agent's hello/state is accepted and ignored; an old agent that still asks and declines acks `declined`, which falls back like any failure). `hub.start(uid, capture, {…, area})` waits `T.ack` (15 s) for the ack (`declined|timeout|busy|ffmpeg|display|offline`); an ok ack may carry `detail`, returned as `note` and added to the card (e.g. `หาหน้าต่าง Discord ไม่เจอ อัดทั้งจอแทน`). Video uses the existing capture chunk API with the signed token as a claim, so it is a `BrowserCapture` with `via: 'agent'`; the agent keeps a local copy in `~/.discord-recorder-agent/recordings/`, deleted once the bot reports `received || ready`, kept if chunks were lost or the result never came, and pruned after 7 days.
  - Agent behaviour: shows `⚪ พร้อม` / `🔴 กำลังอัดจอ` in the terminal and window title, `s` stops locally (stop reason `agent`), `d` cycles displays, `r` takes the slot back, `q` quits. It never records without a `start` and never asks at record time: consent is given once at install (`ให้บอทอัดจอเครื่องนี้ไหม? (y/N)`, stored as `consent: true`; a config from before counts as consented; an old saved `askFirst` is dropped). Capture area `discord`: Windows gdigrab `title=<Discord window title>` resolved at start; macOS crops the display to the Discord window bounds found at start via JXA `CGWindowListCopyWindowInfo` (no extra permission; the crop does not follow a moved window); Linux, or no window found, records the whole screen and acks with a Thai note. An old agent ignores `area` and records the whole screen (the bot can't tell). System audio is not captured; the room audio covers speech.
  - Manual 🖥️ อัดจอ (`screen:me`, an old `screen:start` and `/screen start` with `PUBLIC_URL`) with the presser's agent online (whatever the `mode` setting) is an agent-manual `Session` (`mode: 'manual'`) started by `launch`: public card and room audio at once, ephemeral `🔴 เริ่มอัดแล้ว … ⏳ กำลังสั่งเครื่องของคุณ...`, then `🔴 เริ่มอัดจอเครื่องของคุณแล้ว`. It ends on `⏹️`, the presser leaving voice, max or the agent dropping. A failed start keeps the audio and edits the reply to `⚠️ <why> — บอทยังอัดเสียงในห้องอยู่` with the private link (+📥) into the same session. Without an agent: the private link (below) prefixed `⚠️ เครื่องของคุณยังไม่ได้เปิดตัวอัด…`.
  - Constraints: `src/agent/*` imports only `node:` built-ins and other `src/agent/*` files; `agent-hub.js`, `compose.js`, `browser-capture.js`, `capture-server.js` stay discord.js-free. Never log or put in a URL a token or `Authorization`. The Discord token never reaches an agent file.
  - Install: `install.sh`/`install.ps1` always use their own Node and ffmpeg in `~/.discord-recorder-agent` (`node/`, `bin/`, `app/`), downloaded from upstream and verified against SHA-256 pins in `src/agent/pins.json` (reviewed in git via `npm run build:agent`; nothing is bundled in the image). Agent JS hashes are computed at server start into `manifest.json`. Before any download the installers ask once `ให้บอทอัดจอเครื่องนี้ไหม? (y/N)` (skipped when `config.json` exists; `DRA_CONSENT=y|n` for tests; no tty or no = `ยกเลิกการติดตั้ง ไม่ได้ติดตั้งอะไร`, exit 0, nothing downloaded or paired) and pair with `--pair-only --consent`. A spent token with an existing config skips pairing, so re-running updates. macOS autostart is opt-in (LaunchAgent opening Terminal, so Terminal keeps the Screen Recording permission); Windows via `shell:startup`. Both write a launcher (`start.command` / `start.cmd`) and an uninstaller (`uninstall.command` / `uninstall.cmd`: asks y/N (`DRA_UNINSTALL` for tests), refuses a folder without `app/main.js`, removes the autostart entry and the whole folder; the bot-side device stays until 🗑️ in `/agent` or 90-day pruning), and end with a `📌 คำสั่งที่ใช้ภายหลัง` block (start, uninstall, update = re-run `/agent`).
- **Compose** (`compose.js`, `composeMeeting`): one `meeting.<ext>` per session. Fast path (no re-encode, reuses `mergeAudio`): exactly one segment and room audio not covered by video is ≤15 s at head and tail. Otherwise all segments are re-encoded onto one canvas (largest segment capped 1920x1080, even dims; libx264 `-preset superfast -crf 30`, 15 fps, black fill for gaps, room audio for the whole session plus each segment's own audio at its offset). One compose at a time process-wide (`pending()` -> card text `(คิวที่ N)` when N>1), run under `nice`, timeout max(15 min, meeting length); the timer starts at spawn. On failure it removes the partial file and throws.
- **Nickname** (`updateNick`, called from `stateChanged`): while recording, the bot's per-server nickname is `<display name> - 🔴 กำลังอัดหน้าจอ|อัดจออัตโนมัติ|กำลังอัดเสียง` (`อัดจออัตโนมัติ` when the current segment was started by auto mode; same length, so the 32-unit cap leaves the same room for the name): session live = current segment owner, waiting or link not opened yet = the presser (`rec.owner ?? rec.by`); the nickname from before is kept in `nickBefore` and restored after; changes are serialized per guild, and startup clears a stale tag.
- **Settings** (`settings.js`): per-guild `{shareMode, mode, area, anyoneRecords, minMembers, ...}` in `data/settings.json` (`SETTINGS_FILE`). `mode` is `agent|browser` with `PUBLIC_URL` (default `agent`; saved or env `screen`/`window` read as `agent`), `screen|window` without it. `area` (กรอบอัดหน้าจอ) is `screen` (default) or `discord`: sent to the agent as `start.area`, and the page link gets `?area=discord` (`pageUrl` via `linkArea(s)`: only when the effective mode is not `browser`; in mode `browser` page links ignore a saved `discord`, which can no longer be changed there, while the agent's `start.area` still uses it, including manual 🖥️), so the capture page says `เลือกหน้าต่าง Discord แล้วกด แชร์` and asks `getDisplayMedia` for `displaySurface: 'window'` (a hint only; `monitor` otherwise). `shareMode` is `off` (nothing), `card` (press-to-start) or `auto`; `getSettings` also returns `shareCards = shareMode !== 'off'` (derived, for readers that only ask "any card?"). Filters (rooms, roles, schedule, minMembers, minShareSeconds, notify channel) apply to cards and auto alike. Migration happens at read time only (file untouched), first match wins: a valid saved `shareMode`; a saved boolean `shareCards` -> `card`/`off`; old `autoScreen: true` -> `auto`; old `autoVoice: 'members'` -> `card`; old `autoScreen: false` -> `off`; else the env default: `SHARE_CARDS` `true|card` -> card, `auto` -> auto, `false|off` -> off; unset (or unknown) -> legacy `AUTO_SCREEN=true` -> auto, else off. `autoVoice` always reads `'off'`; presets are gone. `CAPTURE_AREA` (`screen|discord`) is the default `area` for guilds with no saved choice (unknown reads as `screen`).
  - Config UI (`config-ui.js`, `configView(guild, page, opts)`, `configPageOf(sub)`): the quick page (⚙️, `/settings`, the setup message on `guildCreate`) is one select per setting, each option labelled `<setting>: <value>` with a short description: `config:share` (`auto|card|off`), `config:mode` (`agent|browser`, only with `PUBLIC_URL`), `config:area` (`screen|discord`, only with `PUBLIC_URL` and shown only when the mode is `agent`: hidden in mode `browser`), `config:who` (`admins|all` -> `anyoneRecords`, hidden with `ALLOWED_USER_IDS`), then `config:page-limits` (🔧 ตั้งค่าเพิ่มเติม) and `config:done`. The 🔧 tabs `limits` (min, delay, max; `macmode` without `PUBLIC_URL`), `where` (rooms, roles, notify, manager), `time` (days, from, to) start with `config:page-quick` (◀️ กลับ). A selection saves at once and re-renders (`handleConfig` in index.js, which uses `applyConfig` from config-ui.js as its only patch table: `mode` must be in `modes`, numbers reject blank and NaN, `who` accepts only `admins|all`, `days` keeps whole numbers 0-6, de-duplicated and sorted). Old ids still work: `config:share-*`, `config:cards`/`cards-main`, `config:anyone`, `config:page-main` (quick page). `cardsLabel(s, auto)` = `📣 เมื่อมีคนแชร์จอ: **ปิด|ส่งการ์ด|อัดอัตโนมัติ**` (panel, summary). Writes are serialized and atomic (tmp file, then rename).
- **Delivery** (`deliver()`): uploads to Google Drive when `GOOGLE_REFRESH_TOKEN` and `DRIVE_FOLDER_ID` are set and replies with link buttons. Otherwise it attaches the file (10MB cap) or reports the local path. Files land in `recordings/<guildId>-<timestamp>/`. A session ends in `finishSession` -> `composeMeeting` and delivers `meeting.*` as "▶️ ดูวิดีโอ" (also the capture page's Drive redirect) as the only file; on compose failure it delivers up to 3 segment videos plus voice.mp3 with a note. A legacy screen recording (manual Mac / private link) still goes through `finishScreen` -> `mergeAudio` (`src/merge.js`, ffmpeg `-c:v copy`, offset = video start − `VoiceRecorder.startedAt`; browser start = `liveAt`, Mac = `firstFrameAt`) -> `*-with-audio`; on failure the silent video plus voice.mp3 with a note. A voice-only recording delivers just voice.mp3. `deliver()` returns `uploaded`; with `DELETE_AFTER_UPLOAD=true` a recording dir is removed only if every file in it uploaded to Drive and no active recorder (including session segments) uses it.
- **`SCREEN_ENABLED=false`** (set in Dockerfile and k8s): disables host-Mac capture (`screen`/`window`) only. With `PUBLIC_URL` unset nothing else is left, so `/screen`, `/settings` and `/agent` are not registered and all screen and share-card paths are off (voice only). With `PUBLIC_URL` set, `browser` mode and agents keep them.
- **`anyoneRecords`** (⚙️ quick page `config:who`, default off, hidden when `ALLOWED_USER_IDS` is set): opens 🎙️/🖥️/🌐/⏹️ to everyone, in both `canRecord` and `memberCanRecord`. Config (`settings`, `config:*`) stays `isAdmin` only. The sharer's own `screen:me`/`screen:stop` (with tag) and `screen:rec|cont|switch` for their own uid bypass the checks; the session's `cur.owner` may press `screen:stop`.
- **Card queue** (`renderCard(rec, payloadOrFn)`): every write to a recording's card goes through `rec.cardQ`, in call order. A function payload (`liveCardOf(rec)`; room cards use their own `rc.cardQ`) is built when its turn comes and is skipped (null) once `rec.finished`. `putCard` edits the card, else the deferred interaction reply, else posts. Don't call `card.edit` directly.
- **Panel screen buttons and private offers**: with `PUBLIC_URL` the idle panel shows 🎙️ อัดเสียง, 🖥️ อัดจอ (`screen:me`: the presser's agent, whatever the mode setting) and 🌐 อัดผ่านเบราว์เซอร์ (`screen:link`, `/screen start mode:browser`: always the private link, never an agent); the host-Mac `screen:start` button only without `PUBLIC_URL` (an old `screen:start` with `PUBLIC_URL` maps to 🖥️). A private link offer is `private: true`. Its link message is `rec.offerInteraction`, never `rec.interaction` (that would turn it into the public card). `panel()` hides it until it's live. Expiry (5 min) or cancel edits that message to ⌛ with `components: []`. Sessions are public from their start (they record the room at once), so `hiddenStart` only covers private offers.
- **Voice-only fallback** (`POST /api/capture/:id/voice`, state `voice`, `onVoiceOnly` -> `voiceOnly()` in index.js): a device without `getDisplayMedia` (phone) makes the bot record the owner's room instead. Single use (`voiceTried`). Auto: `{ paired: true }`, nothing started. Manual: the private offer ends silently and a public voice card is posted. Any failure returns the offer to `offered`.
- **Restart cleanup**: `settings.cards` (`[[channelId, messageId]]`, kept by `rememberCard`/`forgetCard`; session cards included) lists the live cards. On `clientReady`, `markOrphanCards` edits them to "⚠️ บอทรีสตาร์ทระหว่างอัด" and clears the list; `settings.roomCards` are deleted and `checkShares` reposts for whoever shares now. `settings.nickBefore` keeps the nickname to restore after a restart.
- **`VoiceRecorder.onGone`**: the connection is lost for good (kicked, or no reconnect within 5 s). `voiceGone` ends an unpaired recording (`⚠️ บอทหลุดจากห้องเสียง`), or adds a note to the session's live video, which keeps recording (while waiting, the session finishes).

## Deployment

- `k8s/deployment.yaml` must stay `replicas: 1` with `strategy: Recreate`. Two gateway connections would answer every command twice.
- `k8s/deployment.yaml` also has a Service (ClusterIP 80 -> `http` 8080) and `/healthz` readiness/liveness probes. `k8s/ingress.yaml` exposes only `/capture`, `/static`, `/api/capture`, `/agent`, `/api/agent` (not `/healthz`) with nginx body-size, no request buffering, 120 s read/send timeout (needed by the 25 s agent long-poll) and per-IP `limit-rps`; the host `recorder.example.com` and the TLS secret are placeholders that must match `PUBLIC_URL`.
- Recordings use an `emptyDir` (20Gi; video is about 0.9GB/h per person, doubled while remuxing, plus the compose output); k8s sets `DELETE_AFTER_UPLOAD=true`. `data/` (`settings.json`, `agents.json`) is a 1Gi PVC `discord-recorder-data`; without it every restart loses settings and forces re-pairing. Env: `SHARE_CARDS` (`true`/`auto`/`false`: default share mode for guilds with no saved choice; legacy `AUTO_SCREEN=true` means auto when it is unset), `AGENTS_FILE`, `AGENT_CODE_PAIRING`, `HTTP_MAX_CONNECTIONS`. The real secrets file `k8s/secret.yaml` (copied from `secret.example.yaml`) must not be committed.
- The Docker image copies only `package*.json` and `src/` (the capture page is `src/capture/`, agent files and install scripts `src/agent/`; no Node/ffmpeg bundles). It exposes 8080.
