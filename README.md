# discord-recorder

บอท Discord อัดเสียงใน voice channel และอัดหน้าจอ (เครื่องที่รันบอทบน macOS หรือจอของคนที่แชร์ผ่านเบราว์เซอร์) แล้วส่งไฟล์กลับใน Discord หรืออัปโหลดขึ้น Google Drive

## ใช้งาน

**ครั้งแรก:** ตอนเชิญบอทเข้า server บอทจะถามคำถามเดียว คือให้อัดอัตโนมัติแบบไหน แล้วกดเลือก 1 ใน 3 แบบ
(⛔ ไม่อัดอัตโนมัติ / 🖥️ อัดจอเมื่อมีคนแชร์ / 📋 อัดประชุม เสียง + จอ) เปลี่ยนทีหลังได้ที่ `/settings` หรือปุ่ม ⚙️

**เปิดแผงควบคุม:** พิมพ์ **`@Recorder`** ในแชท · คลิกขวาที่บอท → Apps → แผงควบคุม Recorder · หรือ `/panel` (ปักหมุดไว้ได้)

```
🎛️ Recorder
⚪ ยังไม่ได้อัด — เข้าห้องเสียงแล้วกด 🎙️
⚡ อัดอัตโนมัติ: 📋 อัดประชุม (เสียง + จอ)
[🎙️ อัดเสียง] [🖥️ อัดจอ]
[⚙️ ตั้งค่า] [📁 Google Drive] [🔄]
```

- แผงที่ส่งด้วย `/panel` หรือ `@Recorder` **อัปเดตสถานะเอง** เมื่อเริ่มหรือหยุดอัด
- **การอัดแต่ละครั้งมีข้อความเดียว** ข้อความนี้เปลี่ยนจาก 🔴 กำลังอัด (มีเวลาที่อัดไปแล้วนับเอง และปุ่มหยุด) → ⏫ กำลังอัปโหลด → ✅ พร้อมปุ่มเปิดไฟล์
- **สถานะของบอท** (กดที่ชื่อบอทก็เห็น) จะขึ้นว่า 🔴 กำลังอัด หรือ ⚪ พร้อมอัด
- **ชื่อบอทใน server** บอกว่าใครกำลังอัด เช่น `KAB - 🔴 กำลังอัดหน้าจอ` หรือ `KAB - 🔴 กำลังอัดเสียง` (KAB = ชื่อในเซิร์ฟเวอร์ของคนที่กดอัด/คนที่แชร์ อัดเสียงอัตโนมัติใช้ชื่อบอท) หยุดอัดแล้วกลับเป็นชื่อเดิม บอทต้องมีสิทธิ์ **Change Nickname**
- ปุ่ม 🖥️ อัดจอ ใช้โหมดที่ตั้งไว้ (ทั้งจอ หรือเฉพาะหน้าต่าง `SCREEN_WINDOW_APP` หรือโหมดเบราว์เซอร์ ซึ่งปุ่มจะเป็น 🎥 อัดจอฉัน)

**ใครกดอะไรได้:**
- ทุกคนเปิดแผงควบคุมได้
- อัด/หยุดได้: ผู้ดูแล server (Manage Server) และคนที่มี role ที่เลือกไว้ในตั้งค่า (📍 ห้อง & คน → 🔑)
- **👥 ทุกคนกดอัดได้:** ผู้ดูแล server เปิดได้ที่ ⚙️ ตั้งค่า (หน้าแบบง่าย) ค่าเริ่มต้นปิด เปิดแล้วทุกคนในเซิร์ฟเวอร์กด 🎙️ 🎥 ⏹️ ได้ ส่วนการตั้งค่ายังเป็นของผู้ดูแลเท่านั้น ปุ่มนี้ซ่อนไว้เมื่อตั้ง `ALLOWED_USER_IDS` (รายชื่อนั้นแทนสิทธิ์ทั้งหมด)
- ข้อยกเว้น: คนที่แชร์จอกด 🎥 / ⏹️ ของการอัดจอผ่านเบราว์เซอร์ของตัวเองได้เสมอ ไม่ต้องมี role
- ตั้งค่าได้: ผู้ดูแล server
- ถ้าตั้ง `ALLOWED_USER_IDS` ไว้ รายชื่อนั้นจะใช้แทน "ผู้ดูแล server" (role ที่เลือกยังกดอัดได้)
- คนที่กดอัดไม่ได้จะเห็นข้อความ 🔒 ที่บอกให้ผู้ดูแลเปิด ⚙️ → 👥 (หรือขอ role)
- บอทต้องส่งข้อความในห้องที่กดได้ (และแนบไฟล์ได้ถ้าไม่ได้ตั้ง Drive) ไม่อย่างนั้นจะบอกให้กดจากห้องอื่น

| คำสั่ง | ทำอะไร |
|---|---|
| `/record start` / `/record stop` | อัด / หยุดอัดเสียงในห้องเสียงที่คุณอยู่ (แยกรายคน แล้วรวมเป็น `voice.mp3`) |
| `/screen start [mode]` / `/screen stop` | อัด / หยุดอัดหน้าจอ `mode` ไม่เลือก = ตามที่ตั้งค่าไว้ (`screen`/`window` = จอเครื่องที่รันบอท, `browser` = จอของคุณผ่านเบราว์เซอร์) |
| `/panel` | ส่งแผงควบคุมที่อัปเดตสถานะเอง |
| `/settings` | ตั้งค่าการอัดอัตโนมัติ |

โหมดหน้าต่างจะตัดเฉพาะบริเวณที่หน้าต่างอยู่ตอนเริ่มอัด ถ้าย้ายหน้าต่างหรือมีหน้าต่างอื่นทับระหว่างอัด จะติดมาด้วย
หน้าต่างต้องอยู่บนจอหลัก และไม่ถูกย่อ

### อัดอัตโนมัติ

`/settings` เปิดหน้าแบบง่าย (3 ตัวเลือก) ก่อน กด 🔧 ปรับละเอียด เพื่อดูทุกตัวเลือก เปลี่ยนแล้วบันทึกทันที เก็บแยกต่อ server ใน `data/settings.json`

| แท็บ | ตั้งค่าอะไร |
|---|---|
| 🖥️ การอัด | เปิด/ปิดอัดจออัตโนมัติ, เริ่มเมื่อมีใครสักคนแชร์จอ หรือแชร์จอ + มีคนในห้อง 2–5 คน, อัดทั้งจอหรือเฉพาะหน้าต่าง, อัดเสียงอัตโนมัติ (ไม่อัด / คู่กับการอัดจอ / เมื่อในห้องมีคนครบ ไม่ต้องแชร์จอ) |
| 📍 ห้อง & คน | ห้องเสียงที่เฝ้า, role ที่แชร์จอแล้วให้อัด, ห้องที่แจ้งผล (ว่าง = แชทของห้องเสียง), 🔑 role ที่กดอัด/หยุดได้ |
| 🕘 เวลา | วันและช่วงชั่วโมงที่อัดอัตโนมัติ (ตาม `TIMEZONE`, ข้ามเที่ยงคืนได้ เช่น 22:00–06:00 โดยวันนับตามเวลาปัจจุบัน: ศุกร์ 22–06 จะไม่รวมเช้าวันเสาร์ถ้าไม่ได้เลือกวันเสาร์) |
| ⏳ ความยาว | ต้องแชร์ต่อเนื่องกี่วินาทีก่อนเริ่มอัด (กันแชร์ผิด), ความยาวสูงสุดของทุกการอัด (กันลืมปิด) |

การทำงาน (ไม่ต้อง `/record` ก่อน):

- **อัดจอ** เริ่มเมื่อตรงเงื่อนไข และหยุดเมื่อคนนั้นเลิกแชร์หรือออกจากห้อง
- **อัดเสียงแบบ "เมื่อในห้องมีคนครบ"** บอทเข้าห้องเอง และหยุดเมื่อทุกคนออกจากห้อง
- บอทประกาศในแชทของห้องเสียงทุกครั้งที่เริ่มอัดเสียงอัตโนมัติ เพื่อให้คนในห้องรู้ว่ากำลังถูกอัด
- แบบอัดประชุม: ถ้ามีคนแชร์จอระหว่างประชุม จะได้ข้อความแยกของวิดีโออีกอัน
- ถ้ากดหยุดเอง หรือครบความยาวสูงสุด บอทจะไม่อัดซ้ำจนกว่าคนนั้นจะเลิกแชร์แล้วแชร์ใหม่ (เสียง: จนกว่าห้องจะว่าง)
- ปิดการอัดอัตโนมัติ เอาห้องออกจากรายการ หรือหมดช่วงเวลาที่ตั้งไว้ การอัดอัตโนมัติที่กำลังอัดอยู่จะหยุดทันที
- ความยาวสูงสุดใช้ค่า ณ ตอนเริ่มอัด เปลี่ยนค่าระหว่างอัดจะมีผลกับการอัดครั้งถัดไป

(Discord ไม่ให้บอทรับภาพ screen share ของคนอื่น จึงอัดได้เฉพาะจอเครื่องที่รันบอท หรือจอที่คนแชร์อัดเองผ่านเบราว์เซอร์ ดูหัวข้อ "อัดจอผ่านเบราว์เซอร์")

### เมื่อบอทรีสตาร์ท หรือหลุดจากห้องเสียง

- **บอทรีสตาร์ท** (ดับ, deploy ใหม่, Mac รีบูต) การอัดที่กำลังทำอยู่จะหยุดทันทีและไม่ได้ส่งผล ไฟล์ที่อัดไว้แล้วอาจยังอยู่ในโฟลเดอร์ `recordings/` แต่บอทไม่ส่งให้อัตโนมัติ การ์ดที่ค้างจะเปลี่ยนเป็น `⚠️ บอทรีสตาร์ทระหว่างอัด การอัดนี้หยุดแล้ว` และชื่อบอทในเซิร์ฟเวอร์กลับเป็นชื่อเดิม
- **บอทถูกเตะออกจากห้องเสียง** หรือหลุดการเชื่อมต่อเกิน 5 วินาที การอัดเสียงในห้องนั้นจะจบ การ์ดขึ้น `⚠️ บอทหลุดจากห้องเสียง` และส่งเสียงที่อัดถึงตอนนั้น ถ้าเป็นเสียงที่คู่กับการอัดจอ วิดีโอจะอัดต่อ และผลจะบอกว่าเสียงมีถึงตอนนั้น

## ติดตั้ง

ต้องมี Node.js และ ffmpeg (`brew install ffmpeg`)

```
npm install
cp .env.example .env   # แล้วกรอกค่า
npm start
```

- `DISCORD_TOKEN`, `CLIENT_ID`: จาก Discord Developer Portal (คำสั่งลงทะเบียนแบบ global ใช้ได้ทุก server ที่เชิญบอท)
- `AUTO_SCREEN_USER_IDS`: (ไม่บังคับ) user ID ที่การแชร์จอจะเริ่มอัดวิดีโออัตโนมัติ
- `AUTO_SCREEN`, `AUTO_SCREEN_MIN_MEMBERS`, `SCREEN_MODE`, `AUTO_SCREEN_CHANNEL_IDS`: ค่าเริ่มต้นของ server ที่ยังไม่ได้ตั้งค่าผ่าน `/settings`
- `TIMEZONE`: timezone ของช่วงเวลาอัดอัตโนมัติ (ค่าเริ่มต้น `Asia/Bangkok`)
- `ALLOWED_GUILD_IDS`: server ที่ใช้บอทได้ คั่นด้วย comma บอทจะออกจาก server อื่นเองทันทีที่ถูกเชิญ (แนะนำให้ตั้ง)
- `LEAVE_UNLISTED`: `true` = ตอนบอทเริ่ม ให้ออกจาก server ที่บอทอยู่แล้วแต่ไม่อยู่ใน `ALLOWED_GUILD_IDS` (ค่าเริ่มต้นแค่ไม่สนใจ server นั้น กันพิมพ์ id ผิดแล้วบอทออกจากทุก server)
- `AUTO_SCREEN`: `true` = server ที่ยังไม่ได้ตั้งค่าจะอัดจออัตโนมัติ (ค่าเริ่มต้นปิด)
- `SCREEN_MODE`: `screen` | `window` (เฉพาะ Mac) | `browser` (ต้องตั้ง `PUBLIC_URL`)
- `PUBLIC_URL`, `HTTP_PORT`, `CAPTURE_MAX_MB`, `CAPTURE_TOTAL_MB`, `DELETE_AFTER_UPLOAD`: ดูหัวข้อ "อัดจอผ่านเบราว์เซอร์"
- `SCREEN_DEVICE`: index ของจอจาก `ffmpeg -f avfoundation -list_devices true -i ""`
- ครั้งแรกต้องเปิด Screen Recording ให้ Terminal/Cursor ที่ System Settings → Privacy & Security

## อัปโหลดขึ้น Google Drive

ถ้าตั้งค่าครบ บอทจะส่งลิงก์ Drive แทนการแนบไฟล์ ถ้าไม่ตั้ง จะแนบไฟล์ใน Discord (ไม่เกิน 10MB)

1. ที่ [Google Cloud Console](https://console.cloud.google.com/) สร้าง project แล้วเปิด **Google Drive API**
2. OAuth consent screen: เลือก External แล้วเพิ่มอีเมลของคุณเป็น Test user
3. Credentials → Create OAuth client ID ชนิด **Web application** ใส่ Authorized redirect URI เป็น `http://localhost:53682`
4. ใส่ `GOOGLE_CLIENT_ID` และ `GOOGLE_CLIENT_SECRET` ใน `.env`
5. ใส่ `DRIVE_FOLDER_ID` เป็นรหัสท้าย URL ของโฟลเดอร์ (`drive.google.com/drive/folders/<รหัสนี้>`)
6. รัน `npm run drive-auth` เปิดลิงก์ที่แสดงแล้วอนุญาต จะได้ `GOOGLE_REFRESH_TOKEN` ให้ใส่ใน `.env`
7. รัน `npm start` ใหม่

บัญชีที่อนุญาตต้องมีสิทธิ์แก้ไขโฟลเดอร์นั้น ถ้า OAuth app ยังเป็นโหมด Testing refresh token จะหมดอายุทุก 7 วัน
ให้รัน `drive-auth` ใหม่ หรือ Publish app เพื่อไม่ให้หมดอายุ

ถ้าอัปขึ้น Drive ไม่สำเร็จ บอทจะแนบไฟล์ใน Discord ให้แทน (ถ้าไม่เกิน 10MB ไฟล์ใหญ่กว่านั้นจะบอกที่อยู่ไฟล์ในเครื่อง) ถ้า Drive ตอบว่าการเชื่อมต่อหมดอายุ (`invalid_grant`) ข้อความผลจะบอกให้ผู้ดูแลบอทรัน `npm run drive-auth` ใหม่ แล้วอัปเดต `GOOGLE_REFRESH_TOKEN` (ใน `.env` หรือ secret) และเริ่มบอทใหม่

## อัดจอผ่านเบราว์เซอร์ (ใช้บน k8s ได้)

**เลือกวิธีอัดจอ:** `/settings` → 🔧 ปรับละเอียด → 🖥️ การอัด → **อัดแบบ**
- **จอของคนกด/คนแชร์ ผ่านเบราว์เซอร์** — ภาพมาจากเบราว์เซอร์ของคนที่กด (ต้องตั้ง `PUBLIC_URL`) ใช้บน k8s ได้
- **ทั้งจอ / หน้าต่าง บนเครื่องที่รันบอท** — แบบเดิม ffmpeg อัดจอ Mac ที่รันบอท (ต้อง `SCREEN_ENABLED=true` ใช้ได้เฉพาะ macOS)
- ทั้งสองแบบ บอทเข้าห้องเสียงของคนกด/คนแชร์ไปอัดเสียงคู่กัน แล้วออกเมื่อหยุดอัด
- ถ้าเปิดไว้แบบเดียว ตัวเลือกนี้จะไม่แสดง

Discord ไม่ให้บอทรับภาพ screen share ของใคร โหมดนี้จึงให้ **คนที่แชร์จอเป็นคนอัดเอง** ในเบราว์เซอร์ของเขา แล้วส่งวิดีโอมาให้บอท
ไม่ต้องมีจอบนเครื่องที่รันบอท จึงใช้ได้บน k8s (`SCREEN_ENABLED=false`) และกับหลาย server พร้อมกัน

**ขั้นตอนของผู้ใช้:**

1. **อัดจอเอง:** กด 🎥 อัดจอฉัน ที่แผงควบคุม / `/screen start` (ต้องอยู่ในห้องเสียง) บอทตอบลิงก์ให้เห็นคนเดียว **ยังไม่โพสต์อะไรในห้อง และบอทยังไม่เข้าห้อง** จนกว่าหน้าจะเริ่มอัดจริง
   **อัดอัตโนมัติ:** มีคนแชร์จอในห้องที่บอทเฝ้า → บอทเข้าห้องอัดเสียงทันที และโพสต์การ์ด 🎥 พร้อม ping คนแชร์ (ข้อเสนอนี้ไม่มีเวลาหมดอายุ)
2. **คนแชร์กดลิงก์:**
   - อัตโนมัติ: กดปุ่ม **🎥 อัดจอของฉันด้วย** ที่อยู่บนการ์ดเลย ไม่ต้องกดอะไรก่อน
   - กดเอง: กด **🎥 อัดจอฉัน** บอทตอบเฉพาะคุณ (ephemeral) เป็นปุ่มลิงก์ **🎥 เปิดหน้าอัดจอ**
3. หน้าเว็บเปิดในเบราว์เซอร์บนคอมพิวเตอร์ และเปิดตัวเลือกจอให้เอง (ถ้าเบราว์เซอร์ไม่เปิดให้ ให้กด **▶️ เริ่มอัดจอ**) เลือกจอ/หน้าต่างเดียวกับที่แชร์ใน Discord (ติ๊กแชร์เสียงของแท็บ/ระบบได้ถ้าต้องการ)
4. ระหว่างอัด **ต้องเปิดหน้านั้นค้างไว้** หน้าเว็บส่งวิดีโอเป็นชิ้นละ 3 วินาทีให้บอทเรื่อยๆ การ์ดใน Discord เปลี่ยนเป็น 🔴 กำลังอัด และ**บอทอัดเสียงในห้องของคนแชร์ไปด้วยเสมอ** (ถ้ายังไม่มีการอัดเสียงอื่นใน server อยู่)
5. หยุดเมื่อ: กด ⏹️ ในหน้าเว็บหรือใน Discord, เลิกแชร์จอ, ออกจากห้อง, ครบความยาวสูงสุด, ปิดหน้า/เน็ตหลุดเกิน 45 วินาที, หรือไฟล์ถึง `CAPTURE_MAX_MB`
6. บอทต่อชิ้นส่วนเป็นไฟล์เดียว (ไม่ encode ภาพใหม่) แล้วส่งผลในการ์ดเดิมพร้อมไฟล์เสียงที่คู่กัน ถ้าตั้ง Drive ไว้จะเป็นลิงก์ และ**หน้าเว็บจะเปิดวิดีโอบน Google Drive ให้เอง** (ถ้าอัปไม่ได้ หน้าเว็บจะบอกให้ดูผลใน Discord)

ข้อเสนอส่วนตัวจาก 🎥 อัดจอฉัน หมดใน 5 นาทีและเปิดอัดได้ครั้งเดียว ถ้าไม่มีใครเปิดทันเวลา ข้อความลิงก์จะเปลี่ยนเป็น ⌛ ลิงก์หมดเวลาแล้ว และไม่มีอะไรขึ้นในห้อง ลิงก์บนการ์ดอัตโนมัติไม่หมดเวลาตามนั้น ใช้ได้ตลอดที่ยังอัดอยู่ (หรือถึงความยาวสูงสุดที่ตั้งไว้) แต่เปิดได้ครั้งเดียวเช่นกัน ลิงก์เป็นของคนแชร์คนเดียว อย่าส่งต่อให้คนอื่น เพราะคนที่เปิดก่อนจะได้อัดจอของคุณ

**ตั้งค่า (env):**

| ตัวแปร | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `PUBLIC_URL` | ว่าง | URL สาธารณะของบอท เช่น `https://recorder.example.com` (ไม่มี `/` ท้าย) **ว่าง = ปิดโหมดเบราว์เซอร์** และไม่เปิดหน้าอัดจอ ถ้าไม่ใช่ https (และไม่ใช่ localhost) บอทเตือนตอนเริ่ม เพราะเบราว์เซอร์อนุญาตอัดจอเฉพาะ https หรือ localhost |
| `HTTP_PORT` | `8080` เมื่อมี `PUBLIC_URL` | พอร์ตของ HTTP server ถ้าตั้งโดยไม่มี `PUBLIC_URL` จะเปิดแค่ `/healthz` (ไว้ให้ k8s probe) ที่เหลือตอบ 404 ถ้าไม่ตั้งทั้งคู่จะไม่เปิดพอร์ตเลย |
| `CAPTURE_MAX_MB` | `3072` | ขนาดรวมสูงสุดของวิดีโอต่อการอัด 1 ครั้ง ถึงแล้วการอัดจบพร้อมส่งเท่าที่ได้ |
| `CAPTURE_TOTAL_MB` | `8192` | พื้นที่รวมของชิ้นวิดีโอที่ค้างในเครื่องจากทุกการอัดจอ (กันดิสก์ pod เต็ม) ถึงแล้วการอัดที่กำลังส่งจะจบด้วย "พื้นที่เก็บไฟล์ของบอทเต็ม" |
| `DELETE_AFTER_UPLOAD` | `false` | `true` = ลบโฟลเดอร์ `recordings/<guild>-<เวลา>/` หลังอัปโหลด Drive สำเร็จ **ทุกไฟล์** ในโฟลเดอร์ และไม่มีการอัดอื่นใช้โฟลเดอร์นั้นอยู่ (ต้องตั้ง Drive ด้วย ไม่งั้นไม่ลบ) |
| `SCREEN_MODE` | `screen` | ตั้งเป็น `browser` ให้เป็นโหมดเริ่มต้นของ server ที่ยังไม่ได้ตั้งค่า (หรือเลือกใน `/settings`) ตัวเลือก `browser` จะโผล่เมื่อมี `PUBLIC_URL` |

บน Mac ที่เปิดทั้ง `screen`/`window` และ `browser` ได้พร้อมกัน เลือกโหมดต่อ server ใน `/settings`

**ทดสอบในเครื่อง:**

```
PUBLIC_URL=http://localhost:8080 npm start
```

`localhost` ใช้ได้เฉพาะ **เบราว์เซอร์บนเครื่องเดียวกับบอท** (เบราว์เซอร์ถือว่าปลอดภัยพอให้อัดจอ) ถ้าคนแชร์อยู่คนละเครื่อง ลิงก์ที่ชี้ `localhost` จะเปิดไม่ติด ให้เปิด tunnel เป็น https แล้วตั้ง `PUBLIC_URL` เป็น URL นั้น เช่น
`cloudflared tunnel --url http://localhost:8080` หรือ `ngrok http 8080` (ถ้า URL เปลี่ยนต้องตั้ง `PUBLIC_URL` แล้วรันบอทใหม่)

**Ingress / TLS บน k8s:** `k8s/deployment.yaml` มี Service (ClusterIP พอร์ต 80 → 8080) และ `k8s/ingress.yaml` เปิดสู่ภายนอกเฉพาะ `/capture`, `/static`, `/api/capture` (`/healthz` ไม่ถูกเปิดออกนอก cluster)

1. แก้ `recorder.example.com` ใน `k8s/ingress.yaml` (ทั้ง `tls.hosts` และ `rules.host`) และ `PUBLIC_URL` ใน ConfigMap ให้เป็นโดเมนจริงตัวเดียวกัน
2. ต้องมี TLS: ใช้ cert-manager (เอา comment annotation `cert-manager.io/cluster-issuer` ออกและแก้ชื่อ issuer) หรือสร้าง secret `discord-recorder-tls` เอง **ถ้าไม่มี TLS จริง nginx จะใช้ใบรับรองปลอม เบราว์เซอร์จะขึ้นเตือนและหน้าอัดจอใช้ไม่ได้**
3. `kubectl apply -f k8s/deployment.yaml -f k8s/ingress.yaml`

หมายเหตุ:
- Ingress จำกัด 10 request/วินาทีต่อ IP (`limit-rps`) การอัด 1 หน้าใช้ไม่ถึง 1 ต่อวินาที แต่ถ้าหลายคนอยู่หลัง IP ออฟฟิศเดียวกันจะใช้โควตาร่วมกัน
- ลิงก์อัดจอ (`/capture/<token>`) จะติดอยู่ใน access log ของ nginx คนที่อ่าน log ได้จะเปิดลิงก์ก่อนเจ้าของได้ภายใน 10 นาที ถ้ากังวลให้จำกัดคนเข้าถึง log
- ถ้าคนแชร์เผลอปิดหรือรีเฟรชหน้าอัดจอ การอัดจะจบ ต้องหยุดแชร์ใน Discord แล้วแชร์ใหม่ถึงจะได้ปุ่ม 🎥 อีกครั้ง

Ingress ตั้ง `proxy-body-size: 20m` และปิด `proxy-request-buffering` เพราะชิ้นส่วนวิดีโอใหญ่ได้ถึง 16MB ต่อชิ้น ถ้าใช้ ingress controller อื่นต้องตั้งให้เทียบเท่า
ไฟล์วิดีโอใช้ราว 0.9GB/ชม. ต่อคนที่อัด (และ ×2 ชั่วคราวตอนต่อไฟล์) `emptyDir` ใน manifest จึงตั้ง 20Gi

**เบราว์เซอร์ที่รองรับ:** Chrome, Edge, Firefox, Safari บน **คอมพิวเตอร์** (มือถือไม่รองรับการอัดจอ) ไฟล์ที่ได้เป็น mp4 (H.264) ถ้าเบราว์เซอร์อัดได้ ไม่งั้นเป็น webm (VP8/VP9) ซึ่งเปิดได้ในเบราว์เซอร์และ VLC แต่บางโปรแกรมไม่รองรับ

- **เสียงในวิดีโอ:** เมื่ออัดจอพร้อมเสียงในห้อง บอทรวมเสียงห้อง (`voice.mp3`) เข้าไปในวิดีโอให้เป็นไฟล์เดียว (`screen-with-audio.mp4` / `.webm`, ไม่เข้ารหัสภาพใหม่, จัดเวลาให้ตรงกัน) ปุ่ม ▶️ ดูวิดีโอ เปิดไฟล์นี้ และยังมี 🎧 ฟังเสียง แยกให้ ถ้ารวมไม่สำเร็จจะส่งแยกไฟล์พร้อมหมายเหตุ

**ถ้าคนแชร์เปิดลิงก์บนมือถือ:** หน้าเว็บจะบอกว่าอัดจอไม่ได้ แล้วให้บอทอัดเสียงในห้องแทนโดยอัตโนมัติ ดูผลใน Discord ได้เลย
- กดเอง (🎥 อัดจอฉัน): บอทเข้าห้องที่คุณอยู่ แล้วโพสต์การ์ด 🔴 ใหม่ให้ (อัดได้แค่เสียง) ลิงก์นี้ใช้ได้ครั้งเดียวเหมือนเดิม
- อัตโนมัติ: เสียงในห้องถูกอัดอยู่แล้ว หน้าเว็บจะบอกให้ปิดหน้านี้ได้
- ถ้าคุณไม่ได้อยู่ในห้องเสียง หรือบอทเข้าห้องไม่ได้ หน้าเว็บจะบอกเช่นนั้น และลิงก์ยังใช้จากคอมพิวเตอร์ได้

**ข้อจำกัด:**

- คนแชร์ **ต้องกดเอง** บอทเริ่มอัดให้เองไม่ได้ เพราะ Discord ไม่ให้บอทรับภาพวิดีโอ และเบราว์เซอร์บังคับให้ผู้ใช้เลือกจอเอง ถ้าไม่มีใครกดลิงก์ อัตโนมัติ: บอทยังอัดเสียงในห้องต่อจนการแชร์จบ ผลจะเป็นเสียงอย่างเดียว (ถ้าเข้าห้องไม่ได้และยังไม่มีอะไรถูกอัด การ์ดจะถูกลบเมื่อการแชร์จบ) กดเอง: ข้อเสนอหมดใน 5 นาทีและไม่มีอะไรถูกอัด
- อัดผ่านเบราว์เซอร์ได้ 1 ครั้งต่อ 1 server และเป็นจอของคนที่กดเท่านั้น คนถัดไปจะได้ปุ่มใหม่เมื่อการอัดก่อนหน้าจบ
- ปิดแท็บแล้วอัดต่อไม่ได้ (ได้เท่าที่ส่งมาแล้ว) ถ้าเน็ตสะดุด ชิ้นที่ขาดอาจทำให้วิดีโอมีช่วงหาย บอทจะบอกในผลลัพธ์
- ถ้าบอท restart ระหว่างอัด ลิงก์ทั้งหมดใช้ไม่ได้ และการอัดที่ค้างหยุดทันที (ดูหัวข้อ "เมื่อบอทรีสตาร์ท" ด้านบน)

npm test              # ทดสอบแบบออฟไลน์ ไม่ต้องล็อกอิน Discord ราว 10 วินาที

## รันบอทค้างไว้บน Mac (launchd)

ถ้าอยากให้บอทเริ่มเองหลังล็อกอิน และเปิดใหม่เองเมื่อหยุดทำงาน ใช้ launchd ได้ ไม่บังคับ

1. หา path ของ node ด้วย `which node` (เช่น `/opt/homebrew/bin/node`) แล้วแทนค่าใน `ProgramArguments`
2. สร้างไฟล์ `~/Library/LaunchAgents/com.example.discord-recorder.plist` (เปลี่ยน `com.example` เป็นชื่อของคุณเอง):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.example.discord-recorder</string>
    <key>ProgramArguments</key>
    <array>
        <string>/ABSOLUTE/PATH/TO/node</string>
        <string>/Users/rtliz/discord-recorder/src/index.js</string>
    </array>
    <key>WorkingDirectory</key>
    <string>/Users/rtliz/discord-recorder</string>
    <key>EnvironmentVariables</key>
    <dict>
        <key>PATH</key>
        <string>/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin</string>
    </dict>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/Users/rtliz/Library/Logs/discord-recorder.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/rtliz/Library/Logs/discord-recorder.log</string>
</dict>
</plist>
```

- `PATH` ใส่ไว้เพราะ launchd ไม่โหลด PATH จาก shell ถ้า `ffmpeg` อยู่ที่อื่นให้แก้ตรงนี้
- `WorkingDirectory` ต้องเป็นโฟลเดอร์ของบอท เพื่อให้อ่าน `.env` และสร้าง `recordings/` ถูกที่

```
launchctl load -w ~/Library/LaunchAgents/com.example.discord-recorder.plist     # เริ่มและเปิดเองทุกครั้งที่ล็อกอิน
launchctl unload -w ~/Library/LaunchAgents/com.example.discord-recorder.plist   # หยุดและไม่เปิดเองอีก
tail -f ~/Library/Logs/discord-recorder.log                                    # ดู log
```

- แก้ plist แล้วต้อง `unload` แล้ว `load` ใหม่
- อย่ารัน `npm start` พร้อมกับ launchd ในเครื่องเดียวกันหรือเครื่องอื่น บอทสองตัวจะตอบทุกคำสั่งสองครั้ง
- ถ้าใช้อัดจอเครื่องโหมด `screen`/`window` ต้องให้สิทธิ์ **Screen Recording** แก่ **node** (path เดียวกับ `ProgramArguments`) ที่ System Settings → Privacy & Security เพราะ launchd รัน node เอง ไม่ได้รันผ่าน Terminal
- การอัดที่กำลังทำอยู่จะหายถ้าบอทหยุดทำงาน (เช่น Mac รีบูต)

## Deploy บน Kubernetes

ใน pod ไม่มีจอ จึงตั้ง `SCREEN_ENABLED=false` (Dockerfile ตั้งไว้ให้แล้ว) ซึ่งปิดเฉพาะการอัดจอของเครื่องที่รันบอท (`screen`/`window`) ถ้าไม่ตั้ง `PUBLIC_URL` คำสั่ง `/screen` และการอัดวิดีโออัตโนมัติจะถูกปิดทั้งหมด เหลือ `/record` และอัดเสียงอัตโนมัติ ถ้าตั้ง `PUBLIC_URL` จะอัดจอได้ผ่านเบราว์เซอร์ของคนแชร์ ดูหัวข้อ "อัดจอผ่านเบราว์เซอร์"
`data/settings.json` อยู่ในไฟล์ระบบของ pod ถ้าต้องการให้การตั้งค่าอยู่รอดหลัง restart ให้ mount volume ที่ `/app/data`
ถ้าต้องการอัดจอเครื่อง (ไม่ใช่จอของคนแชร์) ให้รันบอทแบบ local บนเครื่องที่มีจอแทน

```
docker build -t REGISTRY/discord-recorder:latest . && docker push REGISTRY/discord-recorder:latest
kubectl apply -f k8s/deployment.yaml          # แก้ image, GOOGLE_CLIENT_ID, PUBLIC_URL ก่อน
kubectl apply -f k8s/ingress.yaml             # ถ้าใช้อัดจอผ่านเบราว์เซอร์ (แก้ host ก่อน)
cp k8s/secret.example.yaml k8s/secret.yaml    # กรอกค่าลับ (secret.yaml ห้าม commit)
kubectl apply -f k8s/secret.yaml
```

- มี readiness/liveness probe ที่ `/healthz` (พอร์ต `HTTP_PORT`)
- `replicas: 1` + `Recreate` เพราะเป็น gateway bot รันซ้ำไม่ได้
- ไฟล์อัดเก็บใน `emptyDir` (หายเมื่อ pod restart) จึงควรตั้งค่า Google Drive ไว้ ไม่อย่างนั้นไฟล์เกิน 10MB จะไม่มีทางส่งออกมา (ตั้ง `DELETE_AFTER_UPLOAD=true` ได้ เพื่อลบไฟล์หลังอัปโหลดสำเร็จ กันดิสก์เต็ม)
- ไฟล์ PCM ดิบใช้ราว 11.5MB/นาที/คนที่พูด ปรับ `sizeLimit` ตามความยาวการประชุม
